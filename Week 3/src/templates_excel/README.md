# `src/templates_excel/` — Excel Template Generator (Beginner Guide)

> **Simple idea:** Employees need official Excel forms to fill in. Python **creates** those forms automatically — we don't hand-write Excel files manually.

---

## Why generate templates with code instead of copying Excel files?

| Manual Excel files | Generated by Python |
|--------------------|---------------------|
| Can get out of sync with code | Always matches what cleaner expects |
| Employee might edit headers | Headers are programmatically enforced |
| Hard to update instructions | Change one Python file, regenerate |
| Must be committed to git | Created on first server start |

**Real problem this prevents:** Employee deletes a column or renames `MOUVEMENT` to `MOVEMENT` → upload fails mysteriously. Generated template shows exact required format.

---

## The one file: `generator.py`

Uses **openpyxl** library — Python code that can create/edit `.xlsx` files without opening Excel.

---

## Template 1: `generate_product_template()`

**Creates:** `excel_templates/product_catalog_template.xlsx`

### Sheet "Products"

**Row 1 — Headers (blue background, white text):**
```
REFERENCE | COLLECTION | GENDER | MOUVEMENT | DIAL | BRACELET | COLOR | CASE SZE | KIND
```

**Why these exact names?** They match `COLUMN_MAP` in `product_cleaner.py`. Cleaner recognizes all variants, but template uses canonical names.

**Row 2 — Example WATCH:**
```
002H621 | GALIERA | LADIES | QUARTZ | SILVER | MESH | SS | 30 | WATCH
```

**Row 3 — Example COFFRET:**
```
350J621 | MULTIPLES | LADIES | QUARTZ | SILVER | MECH/LEATH | SS/ROSE | 30 | COFFRET
```

**Why two example rows?**  
Shows employees:
- Normal watch vs gift set (COFFRET)
- How combo fields use `/` (MECH/LEATH)
- Required vs optional columns (dial can be filled, case size can be text)

### Sheet "Instructions"

Plain English explanation of each column. Employee can read this without asking IT.

**Why a separate Instructions sheet?** Non-technical users need guidance inside the file they already have open.

## Template 2: `generate_monthly_report_template()`

**Creates:** `excel_templates/monthly_sales_stock_template.xlsx`

### Sheet "Sales Per POS"

Mirrors **January 2024 report structure** — the format `monthly_report_parser.py` expects:

```
Row 1: Pierre Lannier | 1113 - Kingdom Mall - Riyadh - AlHomaidhi | | 1122 - Garnata Center - Riyadh - AlHomaidhi
Row 2: Item Code      | Sales | Cls Stock                          | Sales | Cls Stock
Row 3: 002H621        | 0     | 1                                  | 2     | 0
```

**Why column C is empty between shops?** Matches real report layout — shop blocks are spaced apart.

**How to read row 3 example:**
- Product 002H621 at Kingdom Mall (1113): 0 sold, 1 in stock
- Product 002H621 at Garnata Center (1122): 2 sold, 0 in stock

**Why "Cls Stock" not "Closing Stock"?** Matches original Excel reports exactly — parser looks for "Sales" and adjacent stock column.

## Template 3: `generate_manual_entry_template()`

**Creates:** `excel_templates/bulk_entry_template.xlsx`

Empty sheet with same 9 columns as product template. For employees who prefer Excel over the website form.

**Why exist if website has manual entry?** Some employees are more comfortable with Excel than web forms.

## `ensure_all_templates(templates_dir)`

Called automatically when server starts (`app.py` → `before_request`).

**What it does:**
1. Create `excel_templates/` folder if missing
2. Generate all 3 `.xlsx` files
3. Return dict with file paths

**Why regenerate every start?** Guarantees templates always match current code. Small files, takes milliseconds.

**Returns:**
```python
{
  "product_catalog": Path("excel_templates/product_catalog_template.xlsx"),
  "monthly_report": Path("excel_templates/monthly_sales_stock_template.xlsx"),
  "bulk_entry": Path("excel_templates/bulk_entry_template.xlsx"),
}
```

## Employee journey — template to database

```
1. Employee visits /templates page
2. Clicks "Download Product Catalog"
3. Browser: GET /download/product_catalog
4. app.py: send_file(product_catalog_template.xlsx)
5. Employee opens in Excel, adds 50 product rows
6. Employee visits /upload, selects file, clicks Upload
7. app.py: POST /api/upload/products
8. ProductCleaner reads sheet "Products" (must match template sheet name!)
9. 50 products cleaned and saved to database
```

**Critical:** Upload expects sheet named `"Products"`. If employee renames sheet, upload may fail or read wrong sheet.
